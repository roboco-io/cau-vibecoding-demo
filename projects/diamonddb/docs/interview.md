# 심층 인터뷰 기록

날짜: 2026-10-06. 목적: 프로젝트 설계에 영향을 주는 데이터·사용자·시간 범위 확인.

## 사용자에게 확인한 사항

| 질문 | 응답 | 설계에 반영 |
|---|---|---|
| 어떤 데이터로 역량을 증명하는가? | MLB Statcast 투구 + Chadwick 선수 정보 | 선수 ID 기반 실제 두 출처 연결 |
| 주 사용자와 보여줄 결과는? | 데이터 처리와 간단한 조회 화면, 두 사용자 모두 | DB 품질 기록과 분석용 조회 화면 포함 |
| 라이브 구현 시간 범위는? | 우선 설계와 UI 목업만 빠르게 제작 | 이번 작업은 설계와 가상 화면에 제한, DB·API는 향후 구현 |

## 설계자가 제안한 사항

최초 제안은 로컬 SQLite였습니다. 이후 사용자가 AWS 서버리스 운영, SQL 필수, Aurora DSQL 사용, 월 10만 요청 비용 산정을 요청하여 운영 설계를 변경했습니다. UI는 PC와 모바일에 모두 대응하도록 요청했습니다. 실제 배포 요청은 없으므로 설계·비용·목업만 작업합니다.

서울 단일 리전, 100명 MAU, 저장량·적재량·Lambda 시간·DPU 사용량과 환산 환율은 비용 산정을 위한 가정입니다. 사용자 확정 조건이나 실제 측정값으로 취급하지 않습니다.

학생의 실제 SQL·Python 숙련도, 실제 경기 ID와 자료 접근 성공 여부는 확인하지 않았습니다. 설계 문서에서는 학생의 숙련도나 데이터 확보 성공을 가정하지 않습니다. 구현 단계에서 학습 수준과 입력 확보를 확인합니다.
