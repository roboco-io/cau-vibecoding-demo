# ADR-003: 오류를 격리하고 재적재와 변경 충돌을 구분한다

- 상태: 제안.
- 날짜: 2026-10-06.

## 맥락

단순 결측 제거는 정상 투구를 버릴 수 있고, 무조건 UPSERT는 원본 변경이나 잘못된 입력을 숨길 수 있습니다. 품질 개선에는 오류를 설명하고 다시 처리할 근거가 필요합니다.

## 결정

필수 식별자·형식·양수 조건을 어긴 행은 격리합니다. 입력 내부의 동일 투구 키 그룹은 모든 행을 격리해 먼저 나온 행을 임의로 신뢰하지 않습니다. 선택 측정값 결측과 선수 매핑 실패는 경고로 기록하고 유효 투구의 적재를 허용합니다.

DB에 같은 키·같은 정규화 내용이 있으면 `unchanged`로 집계합니다. 같은 키에 다른 내용이 있으면 `quarantined` 상태의 `CONTENT_CONFLICT`로 기록하고 기존 값을 유지합니다. 원본 오류를 자동 보정하거나 최신 파일이라는 이유로 덮어쓰지 않습니다.

원본 해시·스키마 버전·규칙 버전·선수 매핑 해시를 실행 기록에 저장합니다. Aurora DSQL로 변경한 뒤에도 작은 경기 파일은 정상 투구·품질 기록·완료 상태를 하나의 트랜잭션으로 반영합니다. 단, 쓰기 전에 변경 계획이 2,000행·8MiB·120초 목표 이내인지 확인합니다. 실제 DB 한계와 재시도 정책은 ADR-006을 따릅니다. 초과 입력은 부분 쓰기 없이 거부합니다.

SQLSTATE 40001은 같은 입력으로 전체 트랜잭션을 최대 3회 재시도합니다. 확정적인 입력 오류는 재시도하지 않습니다. S3·SQS 중복 전달은 원본·매핑·규칙 해시의 실행 키로 중복 완료 실행을 확인하여 무시합니다. 사용자의 별도 재검사 요청과 전송 중복을 구분합니다. 파일 오류나 실패 트랜잭션은 정상 데이터를 변경하지 않고 실패 상태를 별도 기록합니다.

## 대안

전체 파일을 행 오류 하나로 거부하면 단순하지만 정상 자료도 사용할 수 없습니다. 자동 보정·자동 덮어쓰기는 편리하지만 데이터 변경의 근거를 잃습니다. 첫 버전에서는 정상 행 적재 + 오류 격리 + 충돌 보존을 선택합니다.

## 결과와 재검토

재실행과 오류 설명이 명확해집니다. 수정 데이터의 승인 반영은 후속 기능입니다. 큰 파일을 나눠 적재하려면 완료 버전 공개와 실패 복구 정책을 별도 설계해야 하며 작은 파일의 전체 롤백을 큰 파일에도 그대로 보장하지 않습니다.
