# ADR-001: 공개 자료를 두 출처로 연결하고 입력을 고정한다

- 상태: 제안. 사용자 선택 데이터는 확정, 구체적 수집·보존 정책은 설계 제안.
- 날짜: 2026-10-06.

## 맥락

구단 DB 직무에는 서로 다른 자료를 통합하는 능력이 필요합니다. 단일 CSV의 차트만으로는 식별자 연결과 구조 분석을 보여주기 어렵습니다. 라이브 중 원격 자료 변경이나 접근 실패도 피해야 합니다.

## 결정

Statcast 한 경기의 투구와 Chadwick의 해당 선수 매핑을 연결합니다. 2025년 자료로 첫 범위를 제한하고, 다운로드 시 Statcast 조회 조건·시각, Chadwick 커밋 SHA, 각각의 파일 SHA-256을 manifest에 남깁니다. 원본은 수정하지 않고 변환·오류 주입본은 별도 파일로 둡니다.

MLBAM ID로 연결하며 이름으로 추정하지 않습니다. 선수 매핑은 UUID를 함께 보존하고 최소한의 이름·ID 필드만 사용합니다. Chadwick의 원문이 설명하는 식별자 변경 가능성을 고려해 매핑 버전을 남깁니다.

pybaseball은 수집 도구 후보입니다. 설치·접근 확인 전에는 의존성을 확정하지 않고 공식 CSV 수동 내려받기도 동일한 입력 계약으로 수용합니다. 실제 입력이 확보되지 않으면 가상 샘플로 핵심 처리를 검증하되 실제 두 출처 통합 완료로 보고하지 않습니다.

## 대안

| 대안 | 장점 | 첫 버전에서 선택하지 않은 이유 |
|---|---|---|
| KBO 비공식 데이터 | 삼성 경기라는 직접적인 맥락 | 원천 조건·추출 코드 허락 및 ID 체계 추가 확인 필요 |
| Retrosheet + Chadwick | 명시적 사용 안내, 식별자 통합 | 측정 구속·위치 중심의 품질 사례가 약함 |
| 가상 데이터만 사용 | 안정적이고 오류 통제 가능 | 실제 외부 자료 연결 증거를 제공하지 못함 |

## 결과와 재검토

외부 소스 두 개를 재현 가능하게 연결할 수 있지만 최신성·국내 구단 맥락은 제한됩니다. API 변경·권한 문제·다년 자료가 필요해지면 이 결정을 재검토합니다. 원본과 파생 샘플의 공개 저장소 포함 여부는 자료별 조건 확인 후 결정합니다.
