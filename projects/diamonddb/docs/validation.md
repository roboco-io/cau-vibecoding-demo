# 검증과 시연 계획

현재 작업은 문서 검사와 UI 목업 확인입니다. 아래 DB·API 검증은향후 계획이며 아직 실행하지 않았습니다.

운영 DB는 Aurora DSQL로 변경했습니다. SQL JOIN·FK·트랜잭션·인덱스 검증은 실제 DSQL dev 클러스터에서 수행해야 합니다. 목업과 비용 계산기의 성공을 DB 기능 검증으로 표현하지 않습니다.

| 사례 | 기대 결과 | 완료 기준 |
|---|---|---|
| 원본과 선수 자료 | 출처·해시·버전 추적 | AC-01 |
| 정상행과 선택 측정값NULL | 정상행 보존, 결측 표시 | AC-02 |
| 필수ID 누락·문자 구속·음수 구속 | 규칙별 격리 | AC-02·03 |
| 입력 중복키 | 그룹 전체 격리 | AC-03 |
| 미등록·모호한 선수ID | 경고, 이름을 만들어내지 않음 | AC-04 |
| 100mph | 저장160.9344km/h, 화면160.9 | AC-04 |
| 동일입력2회 | 투구수·값 불변, 두번째unchanged | AC-05 |
| 동일키의 변경구속 | 기존값 유지, 충돌격리 | AC-06 |
| DB쓰기 중실패 | 롤백, failed 기록 | AC-03 |
| 필터·빈결과·오류조건 | API계약과 화면 일치 | AC-07 |
| 시연용 오류주입본 | 원본의 실제문제와 구분 | AC-08 |

## 서버리스 추가 검증 계획

- SQL 조회: 경기·투수·타자 필터 JOIN, 키 페이지네이션, NULL 표시와 인덱스 실행 계획 비교.
- 인증: JWT 없음·만료·권한 부족, DB 실행 역할의 읽기/쓰기 분리, 브라우저에 IAM 자격 미노출.
- S3·SQS: 같은 manifest 중복 전달, 선수 파일 미확보, 해시 불일치, 보고서 prefix의 재귀 이벤트 방지.
- DSQL: PK/FK, SQLSTATE 40001 전체 재시도, 계획 한도 초과의 쓰기 전 거부, 실패 트랜잭션 롤백.
- 복구: DB 커밋 이후 S3 보고서 저장 실패, 재전달에서 보고서 재생성과 중복 투구 방지, DLQ 재처리.
- 비용: 대표 SQL의 DPU와 Lambda 과금 시간, 월평균 저장량을 측정해 비용 가정을 갱신.
- UI: 390·1280·1440·1920px, PC의 조회·품질 동시 배치, 키보드와 필터·빈 결과·오류 상세.

## 이번 화면 검증

데스크톱과390px 폭, 전체 화면 가로 넘침, 표의 스크롤, 키보드 탐색, 선수 필터, 빈결과, 오류상세를 확인합니다. 경기·선수·속도·건수는 모두가상으로 표시합니다. DB처리와API연동은 완료했다고 표현하지 않습니다.

## 향후 라이브 흐름

출처 설명 → 원본 검사 → 오류주입본 검사 → 정상행 적재 → 재적재 검증 → UI조회 → 검증 결과를 포트폴리오에 연결합니다. 각 단계의 기대값·실제값·명령을 기록합니다. 이번 시연은문서와 화면의 이용 동선을 확인하는 범위입니다.
