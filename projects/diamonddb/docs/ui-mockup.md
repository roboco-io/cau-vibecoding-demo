# UI 목업

사용자 요청에 따라 설계와 목업만 작성합니다. 화면의 경기·선수·구속·건수는 모두 가상입니다. 실제 자료 수집·DB 적재·API 호출은 없습니다.

## 디자인 방향

- 색상: 구장 잔디를 떠올리는 녹색 `#145c43`, 흰색 `#ffffff`, 차가운 바탕 `#eef3f6`, 본문 `#173247`, 경고 `#92500b`, 오류 `#a62b36`.
- 글꼴: 로컬 한글 시스템 글꼴과 일반 sans-serif, 데이터 수치는 탭형 숫자로 정렬.
- 배치: 왼쪽 프로젝트 정보, 위쪽 가상 데이터 안내, 본문은 처리 상태 → 필터와 투구 목록 → 오류 상세 순서. 모바일에서는 한 열로 배치합니다.
- PC 대응 개선: 1440px 이상에서는 투구 조회와 품질 기록을 2:1로 나란히 배치하고 각 영역 안에서 표·필터·상세가 유지됩니다. 1280px에서는 한 열과 고정 탐색 영역, 700px 이하에서는 상단 탐색과 한 열로 전환합니다. 1920px에서도 넓은 공간을 활용합니다.
- 강조: 야구 다이아몬드 형태의 단순 벡터 표식과 읽기 쉬운 기록표. 구단 로고를 사용하거나 공식 제품처럼 표현하지 않습니다.

## 동작 범위

경기·선수 필터, 결과 초기화, 가상 빈 상태, 오류 상세 선택, 투구 조회와 품질 기록 간 이동을 제공합니다. 미구현 적재·다운로드 버튼을 실제 기능처럼 배치하지 않습니다.

## 실행과 검증

[README의 목업 실행 명령](../README.md)을 사용합니다. 브라우저 검증 결과는 작업 완료 후 아래에 기록합니다.

## 확인 결과 (2026-10-06)

- 데스크톱: 가상 투구 6건, 투수 필터 적용 후2건, 빈 경기 선택과 초기화 복귀6건 확인.
- 오류상세: 클릭과 Tab·Enter로 충돌항목 선택·설명변경 확인, 포커스 표시 확인.
- 모바일390px: 페이지 너비390px로 전체 가로넘침 없음, 기록표만 가로스크롤.
- 초기화 버튼의 폼 메서드 이름 충돌을 수정하고 같은 동작을 재검증.
- 화면은여전히 가상자료만 사용하며 실제DB·API 기능 검증은미실행.

## PC 대응 개선 검증 (2026-10-06)

- 1440·1920px에서 투구 조회와 품질 기록의 두 열 배치 확인.
- 1280px에서는 고정 탐색 영역과 한 열 배치, 390px에서는 상단 탐색과 한 열 배치 확인.
- 네 해상도에서 페이지 가로 넘침 없음. 모바일 표는 내부 스크롤.
- 필터 6→2건, 빈 결과, 초기화 6건 복귀, 오류 상세 변경을 재검증.
- PC에서 Tab·Enter 선택과 포커스 표시 확인. 브라우저는 1440px 미리보기로 설정.
