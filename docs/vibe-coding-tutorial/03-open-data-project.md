# 3장: 공개 자료로 직무를 증명할 프로젝트 고르기

> **시간**: 요청 기록 2026-10-06 16:46:57 KST, 데이터 선택 답변 16:52:06 KST. 실제 작업 시간 미측정.
> **비용**: 검색 비용 미확인. 실제 야구 데이터 다운로드·AWS 처리 없음.
> **핵심 발견**: 공개 접근, 데이터 이용 조건, 도구 코드의 라이선스는 서로 다릅니다.

## 상황

단순 야구 차트만으로는 통합 DB 담당자의 업무를 충분히 보여주기 어렵습니다. 실제 두 출처를 연결하고 품질·재적재·API 까지 설명할 수 있는 자료가 필요합니다.

## 실제 프롬프트

```text
채용 공고에서 요구하는 업무 능력을 증명하는 프로젝트를 제안해줘. 우선 관련해서 오픈소스 프로젝트나 오픈 데이터 셋이 있다면 그걸 활용해 보자.
```

심층 인터뷰에서 사용자는 ‘추천안: MLB Statcast 투구 + Chadwick 선수 정보’를 선택했습니다.

## 진행한 일

Exa로 자료와 공식 문서를 조사하고 GitHub API로 코드 라이선스를 보충 확인했습니다. 후보와 한계를 [조사 문서](../../research/baseball-project-proposals-2026-10-06.md)에 기록했습니다.

| 후보 | 프로젝트에서 사용할 부분 | 확인한 조건 |
|---|---|---|
| Statcast | 투구별 구속·위치·경기·선수 ID | 공개 CSV·필드 문서; 자유 재배포 라이선스는 확인하지 못함 |
| pybaseball | 수집 도구 후보 | 코드 MIT, 원천 자료의 권리와 별도 |
| Chadwick Register | MLBAM·UUID 등 선수 식별자 연결 | 데이터 ODC-BY |
| Retrosheet | 경기 이벤트·선수 자료 | 지정된 출처 표시 사용 안내 |
| 비공식 KBO 자료 | 삼성 경기와 국내 맥락 | 게시자 라이선스와 원출처 조건을 구분해야 함 |

KBO 추출 저장소에서는 라이선스 API가 404 였고 루트 LICENSE 도 확인하지 못했습니다. 자료가 공개되어 있다는 이유만으로 코드를 복사하는 기반으로 채택하지 않았습니다.

## 결과

프로젝트는 투구 품질 검사 → 선수 연결 → DB 적재 → 조회 API로 정했습니다. 첫 자료 범위는 2025 년 경기 한 개와 필요한 선수 매핑을 제안했지만 실제 경기 ID·다운로드 성공을 확정하지는 않았습니다. 코드의 기본 데이터 구조와 이용 조건을 조사한 단계입니다.

## 배운 점

타격 속도·각도는 모든 투구에 존재하지 않습니다. 결측을 전부 오류로 분류하면 정상 자료를 버립니다. 원본 오류와 시연용 복사본에 주입한 오류도 분리합니다. 투구 키는 경기·타석·투구 번호를 후보로 두고 실제 샘플에서 유일성을 확인해야 합니다.
