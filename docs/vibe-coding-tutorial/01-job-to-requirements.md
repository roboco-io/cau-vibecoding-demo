# 1장: 채용공고를 읽고 프로젝트의 요구를 찾기

> **시간**: 핵심 목표 제시 2026-10-06 16:41:56 KST. 준비 단계와 중단을 포함한 실제 작업 시간은 미측정.
> **비용**: 이번 프로젝트의 AWS 리소스 사용 작업 없음. AI·검색 비용은 미확인.
> **핵심 발견**: 웹페이지의 텍스트만 읽으면 이미지에 적힌 업무·조건을 놓칠 수 있습니다.

## 상황

중앙대학교 학생들에게 공고에서 요구하는 역량을 찾고, 이를 프로젝트 증거로 바꾸는 과정을 보여줍니다. 앞서 진행한 개인 GitHub 경력 기반 추천은 학생 시연의 요구사항으로 사용하지 않습니다.

시작 저장소는 [README](../../README.md)와 [AGENTS.md](../../AGENTS.md)를 따릅니다. 준비 과정에서는 저장소 URL을 QR로 추가했고 이를 실제 해독해 주소를 확인했습니다.이번 튜토리얼의 핵심 구간은 아래 학생 목표 제시부터 시작합니다.

## 실제 프롬프트

```text
지금부터 중앙대학교 학생들을 위한 라이브 코딩을 진행하려고 해. 지원하려는 분야는 구단에서 DB를 관리하는 직군이야. https://www.samsunglions.com/intro/intro02.asp?act=view&idx=1017353&page=1&keyword=&search=
```

## 진행한 일

1. Exa로 삼성라이온즈 공식 페이지를 조회했습니다. 텍스트에는 제목·게시일·지원 링크가 나오고 핵심 직무는 빠져 있었습니다.
2. HTML의 채용 이미지 주소 3 개를 찾아 직접 읽었습니다. 개인정보가 있는 입력이나 실제 지원서 제출은 없었습니다.
3. 업무를 데이터 품질 점검, 장비별 자료 통합, DB 연결 서비스 유지·개선으로 정리했습니다.
4. [공고 분석](../../research/samsung-lions-db-role-2026-10-06.md)에 출처와 확인 날짜를 남겼습니다.

공고는 경력직이지만 사용자는 다음 단계에서 경력 항목을 제외한 시연용 목표 프로필을 요청합니다. 경력 충족을 꾸미는 대신 직무 역량을 학습 목표로 바꿉니다.

## 결과

| 공고 업무 | 학습할 내용 | 남길 증거 |
|---|---|---|
| 원자료 오류 점검 | 누락·중복·형식 검증 | 오류 보고서와 테스트 |
| 통합 DB 관리 | 스키마·식별자·단위 | 데이터 사전과 매핑 |
| 내부 서비스 개선 | SQL·API·실패 처리 | 조회 예시와 기능 검증 |

공고 URL·게시 상태는 2026-10-06 에 확인한 기록입니다. 나중에 따라 할 때는 현재 원문을 다시 확인합니다.

## 배운 점

검색 요약을 요구사항 전체로 간주하지 않습니다.이미지·첨부파일이 있는지 확인하고, 사실과 학습자의 목표를 분리합니다. 직무·프로젝트·기술은 사용자 선택을 따라 단계별로 정합니다.
