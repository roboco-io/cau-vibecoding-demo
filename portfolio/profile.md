# 구단 데이터를 신뢰할 수 있는 정보로 연결하는 통합 DB 개발자

> 중앙대학교 라이브 코딩 시연을 위한 **가상 목표 프로필**입니다. 아래 역량은 시연에서 구현·검증할 목표이며, 실제 학생의 보유 능력이나 완료된 성과를 뜻하지 않습니다.

## 소개

저는 야구 데이터를 정리하고, 일관된 구조로 저장하고, 구단 구성원이 필요한 정보를 조회할 수 있도록 연결하는 개발자를 목표로 합니다. 데이터를 모으는 데서 끝내지 않고 **오류를 발견할 수 있는 검증 과정과 다시 실행할 수 있는 처리 과정**을 함께 설계합니다.

바이브 코딩으로 요구사항을 작은 기능으로 나누고, AI 코딩 에이전트와 함께 데이터 처리 코드·SQL·API·테스트를 구현합니다. 검증 기준을 먼저 정하고 결과를 직접 확인하며, 데이터의 의미와 구현의 정확성에 대한 판단은 제가 맡습니다.

## 수행할 수 있도록 준비하는 업무

### 데이터 품질을 점검하고 문제를 설명합니다

- 필수 항목이 빠진 데이터, 중복 기록, 잘못된 형식과 허용 범위를 벗어난 값을 검사합니다.
- 문제가 있는 데이터를 정상 데이터와 구분하고, 원본 위치·오류 유형·확인 필요 사항을 보고서에 남깁니다.
- 장비나 공급 업체와 확인해야 할 내용을 재현 가능한 샘플과 함께 정리합니다. 이상값을 근거 없이 삭제하거나 임의로 채우지 않습니다.

### 서로 다른 데이터를 하나의 DB 구조로 연결합니다

- 입력별 필드 이름·자료형·단위·식별자를 비교해 공통 구조와 매핑 규칙을 설계합니다.
- 원본과 변환 이력을 보존하고, 선수·경기·측정 기록의 관계를 정리합니다.
- 같은 파일을 다시 처리할 때 중복 적재를 막고, 처리 건수와 실패 내역을 확인할 수 있도록 만듭니다.

### 필요한 데이터를 조회하는 내부 도구를 만듭니다

- 선수·경기·기간 조건으로 데이터를 조회하는 SQL과 API를 작성합니다.
- 데이터가 없는 경우, 잘못된 요청, 처리 실패를 구분해 사용자에게 안내합니다.
- 분석 담당자가 필드의 의미를 이해하도록 데이터 사전과 API 사용 예시를 제공합니다.

### 수정해도 신뢰할 수 있는 시스템을 유지합니다

- 데이터 검증·적재·조회 기능에 정상 사례와 오류 사례를 포함한 테스트를 작성합니다.
- 입력 구조가 달라졌을 때 영향을 확인하고 변경 이유를 기록합니다.
- 실행 방법과 문제 확인 절차를 문서화해 다른 사람이 이어서 사용할 수 있도록 합니다.

## 바이브 코딩을 업무에 활용하는 방식

**문제 정의 → 작은 구현 → 직접 실행 → 검증 → 개선**의 순서로 작업합니다.

| 단계 | AI와 함께 하는 일 | 제가 확인하는 일 |
|---|---|---|
| 문제 정의 | 요구사항을 입력·출력·완료 기준으로 정리 | 구단 업무와 데이터 의미에 맞는지 판단 |
| 설계 | DB 구조와 데이터 변환 규칙의 대안 비교 | 식별자·단위·관계·원본 보존 기준 결정 |
| 구현 | 검증 코드, 적재 과정, SQL, API 초안 작성 | 작은 기능부터 실행하고 코드와 결과 검토 |
| 검증 | 누락·중복·잘못된 값 등 오류 사례와 테스트 작성 | 예상값과 실제값 비교, 재실행 시 중복 여부 확인 |
| 개선 | 실패 원인 분석과 수정안·문서 초안 작성 | 수정 전후 테스트를 확인하고 변경사항 설명 |

빠르게 만든 기능을 **확인 가능한 결과물**로 연결하는 것이 바이브 코딩의 활용 목표입니다. 실제 개인정보·비밀 키·비공개 장비 데이터를 승인 없이 AI 도구에 입력하지 않으며, 실습에는 가상 데이터를 사용합니다.

## 시연을 통해 보여줄 증거

아래는 아직 수행하지 않은 검증 목표입니다. 프로젝트를 선택하고 실행한 뒤 실제 결과와 링크를 추가합니다.

- 오류를 포함한 가상 입력 자료와 데이터 품질 점검 결과.
- 서로 다른 입력 구조를 공통 DB 구조로 변환하는 매핑 표와 데이터 사전.
- 재실행해도 중복이 생기지 않는 적재 과정의 검증 결과.
- 조건별 조회 API의 요청·응답 예시와 기능 테스트 결과.
- AI와 협업한 과정에서 제가 결정한 사항, 발견한 오류, 수정 내용과 한계.

## 목표 직무와의 연결

삼성라이온즈 통합 DB 관리 공고의 **원자료 품질 점검, 장비별 데이터 통합, DB 연동 내부 시스템 유지·개선**에 맞춰 구성했습니다. 경력 항목은 포함하지 않았습니다. 실제 TrackMan·Hawk-Eye 장비 연결이나 구단 시스템 운영 경험을 주장하지 않으며, 시연에서는 가상 데이터로 관련 처리 과정을 검증합니다.
